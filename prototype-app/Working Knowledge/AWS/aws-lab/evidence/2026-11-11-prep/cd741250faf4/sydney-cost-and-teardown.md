## Teardown procedure

1. **Identify the disposable resources.** Verify STS account `736486260824`, region `ap-southeast-2`, the default Terraform workspace, and state key `standard/lab/terraform.tfstate`. Use the same reviewed Terraform revision, inputs and remote backend that created the lab. Save resource IDs and the state inventory in protected storage. Reconcile any partially created resources against Terraform state and AWS inventory. Stop writers and verify that all data and identities in scope are disposable. Preserve the state bucket, its AWS-managed S3 key and the plan role.
2. **Prepare a teardown copy of the configuration.** In an isolated copy for the Sydney lab, remove `prevent_destroy` from the RDS instance, Cognito pool, lab artifact buckets and the two foundation KMS keys. Set the RDS deletion protection to `false`, Cognito deletion protection to `INACTIVE`, RDS `skip_final_snapshot = true` and `delete_automated_backups = true`, and omit `final_snapshot_identifier`. Review a regular Terraform plan that contains only the expected RDS and Cognito updates, then apply that plan with the authorized teardown role. Read back both deletion protection settings before continuing. Skipping final and retained automated backups assumes verified disposable data and approval of that disposition. If a backup must be kept, record its expiry and cost and preserve its encryption key until the backup can be removed. [Terraform lifecycle rules](https://developer.hashicorp.com/terraform/language/meta-arguments/lifecycle#prevent_destroy) · [RDS deletion](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_DeleteInstance.html) · [Cognito deletion protection](https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-settings-deletion-protection.html)
3. **Check the data paths before destroy.** Verify the ECR repository `scoutgrid-lab-backend` is empty. Check `scoutgrid-lab-736486260824-imports` and `scoutgrid-lab-736486260824-exports` for current and noncurrent versions, delete markers and incomplete multipart uploads. If any exist, review the inventory and clear only approved disposable data and multipart uploads in these buckets. Keep both foundation KMS keys usable until those checks are complete. [Emptying a versioned S3 bucket](https://docs.aws.amazon.com/AmazonS3/latest/userguide/empty-bucket.html)
4. **Review and execute a saved destroy plan.** Run `terraform plan -destroy -var-file=sydney-lab.foundation.tfvars -lock-timeout=30s -out=<private-path>` in the teardown copy. Review every deletion against the recorded IDs and reject any create, update, replacement, production resource or state bucket entry. Apply the saved destroy plan after teardown authorization. Let Terraform remove dependent Cognito resources, including the domain, before the pool, and schedule deletion of the two foundation KMS keys after the consumers are removed. If execution stops partway, reconcile state and AWS before producing a fresh destroy plan. [Terraform destroy planning](https://developer.hashicorp.com/terraform/cli/commands/plan#planning-modes) · [Cognito pool deletion](https://docs.aws.amazon.com/cognito-user-identity-pools/latest/APIReference/API_DeleteUserPool.html) · [KMS key deletion](https://docs.aws.amazon.com/kms/latest/developerguide/deleting-keys.html)
5. **Verify that billable resources are gone.** Check that the DB instance, both NAT gateways and both allocated public IPv4 addresses are gone, and that the Cognito pool, Amplify app, ECR repository and both lab artifact buckets are absent. Check for retained RDS backups, manual or final snapshots, and the RDS-managed secret using metadata only. Verify both foundation keys are pending deletion with recorded dates and check again after those dates. AWS does not charge for customer-managed KMS keys while scheduled for deletion. Confirm that the Terraform state has no managed lab resources and the lock was released. Compare the final bill after Cost Explorer updates. [NAT gateway operations](https://docs.aws.amazon.com/vpc/latest/userguide/nat-gateway-working-with.html) · [RDS-managed secrets](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/rds-secrets-manager.html) · [KMS pricing](https://aws.amazon.com/kms/pricing/)
