What changes and why

Reuse the existing ScoutGrid pages. This review shows where AWS changes how those pages connect to provisioning, managed sign-in, and background processing.

Join and work in the right workspace
Use the existing Request a demo entry point. Once the platform owner approves the request and the workspace is ready, send the designated tenant administrator a password setup email. Use managed sign-in and reuse the workspace picker and header.
Keep approval in the existing console
Use Platform → Demo Requests for approval and request status. Use the reviewed provisioning task and runbook for Standard setup and retry.
Make data collection status accurate
Use the existing Connectors → Sources catalog and its connector pages for inventory setup. Adapt the manual upload form inside BOM Management for S3-backed uploads. Use the existing Run History, Inventory, and Findings pages to verify results.

01 · Existing pages

Request and approve a workspace

Request a demo
The requester submits the existing public form at /demo/contact.
Platform → Demo Requests
The platform owner reviews and approves the request in the existing console at /platform/demo-requests.
AWS integration
Route the approved request through Standard provisioning. After activation, send the designated tenant administrator the password setup email. Use the existing request status and the operator runbook for setup or delivery failures.

02 · Existing entry points

Set your password and sign in

Password setup and sign-in
The administrator opens Set your password from the setup email and uses the temporary password from the message. Cognito prompts the administrator to choose a password before opening the approved workspace.
AWS integration
Reuse the existing sign-in page (/login) to hand off to Cognito-managed account setup and sign-in. Keep the approved workspace and role linked to the verified account.

03 · Existing workspace access

Verify workspace access after sign-in

Tenant administrator
After password setup and sign-in, a tenant administrator with one workspace enters it directly. The existing header shows the active workspace.
Platform owner
Use Settings → Authorized Workspaces (/authorized-workspaces) to open a workspace through an authorized membership or an accepted support grant. The existing page shows the access type and expiry.
Workspace access checks for AWS launch
  • Sign in with Cognito and confirm the single-workspace admin enters the approved workspace with the correct role.
  • Open two authorized workspaces in separate tabs as a platform owner. Switching one tab leaves the other tab's workspace and data intact.
  • Confirm SG Internal requires explicit internal membership. Verify that expired or revoked grants, suspended workspaces, and unauthorized requests are denied.

04 · Existing connector pages

Inventory setup in Connectors → Sources

Open Connectors → Sources from the left navigation and choose a card under Inventory.

AWS Discovery
Use the existing form to save the customer role and scope. Configure the role trust with the generated External ID, then use Test Connection and Run Integration Now.
GitHub
Use the existing pipeline form to save the source and its credentials. Use Run Now on a saved pipeline or let it run on schedule. Update the credential hint in the existing form to reflect tenant credentials and supported anonymous access.
Review results
Use Connectors → Run History for execution status and the existing Inventory views to confirm assets or BOMs were imported.
Connector checks for AWS launch
  • Verify the AWS account binding, role trust, and External ID. Verify private GitHub and GHCR credential requirements and supported anonymous sources.
  • Check scheduled and manual runs. Distinguish access errors, throttling, a completed run with no results, and a successful inventory update in the existing views.
  • AWS Discovery and GitHub are in the readiness record. AWS static AI posture depends on entitlement and qualification. Other providers require a confirmed launch need and separate qualification.

05 · Existing BOM Management page

Import a BOM and review its result

Start the import
From the left navigation, open Connectors → Sources → BOM Management. Use Ingest Now → File Upload and submit the file with the existing form.
Track the import
Wire the existing form to S3-backed upload and show transfer progress, acceptance, or validation errors in place. Extend the existing Connectors → Run History view to show queued, running, and completed manual imports, so users can return to an accepted job.
Review results
Use the existing BOM Management result area for the import outcome, BOM Inventory for imported components, and Findings once assessment results are available.
Import checks for AWS launch
  • Verify that the user can leave after acceptance and find the same job on return. Recover an interrupted transfer without creating a duplicate import.
  • Show validation or permission failures through the existing form and run status where authorized.
  • Preserve the existing source replacement and complete-coverage controls. Verify that assessment can continue after the import completes.
