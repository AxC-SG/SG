# Review of additional AI findings feedback

Reviewed October 12, 2026 against the current workspace. The pasted text contains truncated sentences, so this review addresses the identifiable claims without supplying missing wording. This is a correctness review, not an implementation change.

## Findings that change the priority

**P1: evaluation bypasses the distributed policy version.** Confirmed using PostgreSQL against the seeded V1 catalog: the evaluator's policy selection query returns VALIDATED, unpublished 1.0.1 for **16** AWS/Azure policies whose distribution is pinned to published 1.0.0. The evaluator joins distribution by policy_id only, accepts VALIDATED/APPROVED versions, and orders nullable published_at descending. Fixing NULL ordering alone is insufficient: evaluation must honor pinned_version and the applicable approval/digest/release binding. See [AiGridAssessmentService.java:320](</Users/gowrikarthik.gadela/Desktop/AI Projects/NoScan/prototype-app/backend/src/main/java/com/prototype/vulnwatch/aisecurity/service/AiGridAssessmentService.java:320>).

**P1: AI-BOM correlation loses multi-hop applicability and cannot repair partial writes.** Two focused unit regressions failed:

1. Model → wrapper → vulnerable library: no vulnerability link is produced, because traversal stops after the model's direct outgoing edges.
2. Link save succeeds, subject insert fails, then the next reconciliation sees the existing link: it skips the missing subject insert forever. The test simulates the persisted-link state; it is a service-level reproduction, not a database failure-injection test. Static transaction inspection confirms there is no surrounding transaction on the scheduler/service path, so the JPA save and JDBC insert are not atomic.

See [AiBomResourceVulnerabilityCorrelationService.java:120](</Users/gowrikarthik.gadela/Desktop/AI Projects/NoScan/prototype-app/backend/src/main/java/com/prototype/vulnwatch/service/AiBomResourceVulnerabilityCorrelationService.java:120>) and [AiBomResourceVulnerabilityCorrelationService.java:138](</Users/gowrikarthik.gadela/Desktop/AI Projects/NoScan/prototype-app/backend/src/main/java/com/prototype/vulnwatch/service/AiBomResourceVulnerabilityCorrelationService.java:138>). These are visibility/correlation bugs; this service deliberately does not create canonical CVE findings.

## Lower-priority notes

- PREVIEW/out-of-scope governance closure appears intentional; it must not be described as verified remediation.
- Map.of null rejection is a defensive-contract risk; no additional reachable crash was established here.
- Rollout FAILED tasks retry after one minute without an attempt cap. This is a reliability/operations design decision, not direct evidence of broken finding creation.
- Switching the tenant guard from WARN to FAIL is optional hardening requiring verification of legitimate transaction/context entry paths. It does not prove every background path is already correct.

## Recommended order

1. Make policy resolution honor distribution pins and release bindings, and reuse it consistently across evaluation/catalog/coverage views.
2. Reconcile selection/default changes and policy edits across all relevant authoritative scope heads. Preserve explicit tenant overrides.
3. Repair AI-BOM multi-hop traversal, atomic link/subject writes or retry repair, and isolate tenant scheduler failures.
4. Correct exposure SLA recovery, suppression, aggregate state, and one-row-per-finding rendering/filtering.
5. Add precise malformed-policy isolation and expired-relationship regressions before changing transaction/closure behavior. Surface failed assessments as explicit gaps/errors; a naive catch-and-continue inside a failed database transaction is insufficient.
6. Repair the status filter and targeted projection refresh gaps. Keep paused guardrail drift behind its release gate.
